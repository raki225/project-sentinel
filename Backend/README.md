# Project Sentinel — Backend

AI-powered Infrastructure Oversight & Decision Intelligence Platform. Node.js + Express +
TypeScript + MongoDB backend that ingests government infrastructure documents (PDF, DOCX,
PNG, JPG), extracts their text (digital PDF parsing, DOCX parsing, or OCR for images),
sends the extracted text to an AI provider for structured analysis, and serves the result
as a report.

## Stack

Express, TypeScript, Mongoose/MongoDB, Multer, JWT, Zod, pdfjs-dist (PDF text extraction),
Tesseract.js (OCR for images), Sharp (image preprocessing), Mammoth (DOCX), Winston
(logging), Swagger/OpenAPI, Helmet, express-rate-limit.

## Setup

```bash
npm install
cp .env.example .env   # then fill in the values described below
npm run dev             # starts on http://localhost:5000 with ts-node
```

`MONGODB_URI` in `.env` is currently a MongoDB Atlas cluster (`cluster0.lmqpwiq.mongodb.net`,
database `project_sentinel`) — verified working. To use local MongoDB instead, set it back
to `mongodb://127.0.0.1:27017/project_sentinel` and have a local `mongod` running.

## Configuring the AI provider

No AI provider is hardcoded anywhere in the code. Everything is read from `.env`:

```
AI_API_KEY=your-key
AI_API_URL=https://your-provider.example.com/v1   # base URL, no trailing /chat/completions
AI_MODEL=your-model-name
```

The integration (`src/services/aiService.ts`) calls
`POST {AI_API_URL}/chat/completions` with an OpenAI-compatible request body
(`{ model, messages, response_format: { type: "json_object" } }`) and a
`Authorization: Bearer {AI_API_KEY}` header. This works out of the box with OpenAI,
Groq, OpenRouter, and any other OpenAI-compatible endpoint — swap providers by editing
`.env` only, no code changes needed. If you're on Google Gemini's native API (not an
OpenAI-compatible proxy in front of it), `aiService.ts` is the one file to adapt since
Gemini's request/response shape differs.

**Currently in `.env`**: `AI_API_URL=https://api.openai.com/v1` was tried and OpenAI
rejected the supplied key (`401 invalid_api_key`) — so that key belongs to a different
provider or a proxy in front of one. Update `AI_API_URL` (and `AI_MODEL` if needed) once
you confirm where the key is actually issued from, then re-run `/api/analyze/:id`.

## API

Full interactive docs at `GET /api-docs` (Swagger UI) once the server is running.

| Method | Route                | Auth | Description |
|--------|-----------------------|------|--------------|
| POST   | `/api/auth/register`  | —    | Create a user, returns a JWT |
| POST   | `/api/auth/login`     | —    | Log in, returns a JWT |
| POST   | `/api/upload`         | none | Upload a PDF/DOCX/PNG/JPG/JPEG |
| POST   | `/api/analyze/:id`    | none | Extract text + run AI analysis, stores a Report |
| GET    | `/api/report/:id`     | none | Fetch the generated report |
| GET    | `/health`             | —    | Liveness check |

**Auth is currently disabled on upload/analyze/report** — anyone who can reach the API can
call them, no token needed. `register`/`login` and the JWT middleware
(`src/middleware/auth.ts`) are still there, unused; to re-lock the API, add
`authenticate` back into `src/routes/uploadRoutes.ts`, `analyzeRoutes.ts`, and
`reportRoutes.ts` (each still imports `Router` at the top; add
`import { authenticate } from "../middleware/auth";` and drop it into the relevant
`router.post`/`router.get` call). Do this before any real deployment.

A ready-to-import Postman collection with sample requests/responses is at
`postman/Project-Sentinel.postman_collection.json`.

## Geocoding

`GOOGLE_MAPS_API_KEY` in `.env` enables `src/services/geocodingService.ts`, which resolves
the AI-extracted `district`/`department` text to coordinates via the Google Maps
Geocoding API. It's called automatically during `/api/analyze/:id` and the result is
stored on the report as `location: { lat, lng, formattedAddress }`. It's best-effort —
if the key is missing or nothing matches, `location` is just omitted; analysis never
fails because of it.

## Scanned PDFs

Digital PDFs (with a real text layer) are parsed directly via `pdfjs-dist`. Standalone
images (PNG/JPG/JPEG) go through Tesseract OCR. Scanned (image-only) PDFs are *detected*
but not rasterized+OCR'd in this build, since that needs a PDF-to-image renderer — an
external binary dependency (e.g. poppler) deliberately left out to keep setup
dependency-free. `POST /api/analyze/:id` returns a clear 422 error naming this when it
happens; the practical workaround is exporting the scanned PDF's pages as PNG/JPG and
uploading those instead. To add real support, wire a renderer into
`src/services/extractionService.ts` and feed its output through
`src/services/ocrService.ts`.

## Project structure

```
src/
  config/       env, database connection, swagger setup
  controllers/  request handlers
  routes/       Express routers + OpenAPI JSDoc annotations
  middleware/   auth (JWT), validation (zod), rate limiting, multer upload, error handling
  models/       Mongoose schemas: User, Document, Report, AuditLog
  services/     pdf/docx/ocr extraction, AI client
  prompts/      the AI extraction prompt
  types/        shared TypeScript types
  app.ts        Express app wiring
  server.ts     entrypoint (DB connect + listen)
scripts/        one-off scripts (demo PDF generator)
uploads/        uploaded files land here (gitignored)
demo/           synthetic sample document
postman/        Postman collection
```

## Security notes

Helmet security headers, CORS restricted to `CORS_ORIGIN`, rate limiting, Zod input
validation, Multer file-type/size allowlisting are all active. JWT auth exists
(register/login work) but is **not enforced** on upload/analyze/report — see the API
table above for how to re-enable it. Rotate `JWT_SECRET` and all API keys before any
real deployment; `.env` is gitignored.
